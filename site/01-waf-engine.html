01 · WAF ENGINE

ชั้นป้องกันหลัก: ModSecurity CRS + engine เสริมที่เขียนเอง

ทุก request ต้องผ่านชั้นนี้ก่อนถึง origin จริง — สถาปัตยกรรมนี้เรียกตัวเองในโค้ดว่า "CloudWAF Control Plane"

ทำงานที่: Main Node (waf-nginx) + Edge Node (cdn-edge-node) เอนจินหลัก: ModSecurity v3 + OWASP CRS v3

§1 เทคโนโลยีที่ใช้

ModSecurity v3OWASP CRS v3owasp/modsecurity-crs:nginx ngx_http_headers_more_filter_moduleFastAPI + SQLite (control-api) 99-rulesync.sh (POSIX shell)bola_guard.pypayload_normalizer.pysafe_regex.py (RE2)

PARANOIA level = 1, inbound anomaly threshold = 10 (ค่า default) — แต่ที่ Edge Node มีไฟล์ override บีบ threshold ให้เข้มขึ้นเหลือ inbound = 5 แปลว่า control plane tune ความไวของ WAF ต่างกันได้ต่อ node

§2 Custom rule ที่ active จริงตอนนี้

อ่านจากไฟล์จริงบน Main Node และ Edge Node — ทั้งหมดเป็น keyword-matching แบบง่าย (proof-of-concept) ไม่ใช่ signature ป้องกันเชิงลึก

IDMatch on REQUEST_URIActionหมายเหตุ

100002contains pwd01403 CRITICALrule ทดสอบ

§3 ความสามารถ

Rule sync pipeline (Edge ↔ Control Plane)ทำงานจริง

control-api รวมไฟล์ .conf/.txt + blocklist เป็น .tar.gz — edge poll ทุก 5 วิ เทียบ SHA-256, nginx -t เช็ค syntax ก่อน reload แบบไม่ downtime

Global IP Blocklistทำงานจริง

POST/DELETE /api/blocklist (auth ด้วย X-Control-Token) เก็บ IP ใน SQLite แล้ว auto-generate @ipMatchFromFile rule

BOLA/IDOR Guardเครื่องมือตรวจ — ไม่ได้อยู่ใน request path

bola_guard.py (684 บรรทัด) — ตรวจ JWT signature จริง, path canonicalization กัน traversal desync, เช็ค header spoofing (X-User-ID/X-Tenant-ID) ให้ตรงกับ claim ที่ verify แล้ว

แก้คำอธิบาย 2 ก.ย. 2026: ตรวจซ้ำด้วยการไล่ import graph พบว่าโมดูลนี้ถูกเรียกจาก api/rules.py เท่านั้น และ main.py มี middleware แค่ CORSMiddleware ตัวเดียว — แปลว่าเป็น เครื่องมือตรวจแบบเรียกเอง (on-demand) ผ่าน POST /api/rules/bola/inspect ไม่ใช่ยามที่ยืนเฝ้า traffic จริง ดูหลักฐานที่ หน้า 19 §5.1

Payload Normalizationทำงานจริง

แก้ WAF evasion: unicode homoglyph, double/triple percent-encoding (%2527→%27→'), HTML entity obfuscation, null-byte, SQL comment splitting

ReDoS-safe regex executionทำงานจริง

safe_regex.py รองรับ RE2 (linear-time) + fallback process-isolated พร้อม hard SIGKILL timeout กัน CPU worker ค้าง

AI-assisted mitigation candidateทำงานจริง

POST /api/rules/mitigate-candidate รับ log จริงแล้ว auto-generate SecRule ผ่านการเช็ค ReDoS-safety ให้ admin ตรวจก่อนใช้

Blast Radius Simulatorทำงานจริง

เอา rule ที่จะ deploy ไป "เล่นซ้ำ" กับ traffic จริงในอดีต ประเมิน false positive ก่อน sync — ระดับเดียวกับ WAF เชิงพาณิชย์ใหญ่

Rule signature ยังอยู่ระดับ demoหนี้เทคนิค

ยังไม่มี custom rule ที่ป้องกันการโจมตีเฉพาะทางจริง (เช่น CVE เจาะจง หรือ business-logic abuse) นอกเหนือจาก CRS มาตรฐาน

พังจริง — ยืนยันจาก log

waf-nginx (Main Node) สถานะ unhealthy ต่อเนื่อง FailingStreak 3212 ครั้ง ทุก 30 วิ (exit code 7) — healthcheck ยิง curl http://127.0.0.1:80/healthz แต่ nginx จริงฟังที่ port 8080 เท่านั้น เป็น mismatch ระหว่าง default healthcheck ของ base image กับ port ที่โปรเจกต์ override — nginx รับ traffic ได้ปกติจริง เป็นแค่ false alarm ที่ทำ monitoring เข้าใจผิด

ยังไม่มีข้อมูล

global_whitelist.txt และ global_blocklist.txt บน Edge Node ว่างเปล่า — โครงสร้าง sync พร้อมแล้วแต่ยังไม่เคย block IP ผ่าน dashboard จริง

§5 Scenario: SQL Injection request เข้ามา

GET /vulnerabilities/sqli/?id=1' OR '1'='1&Submit=Submit เข้าที่ dvwa.waf-it-kku.online

  1. Caddy

    รับ TLS, terminate SSL, ส่งต่อเป็น HTTP ภายใน docker network ไปยัง waf-nginx

  2. Rate limit check

    nginx เรียก auth_request /internal-rate-limit ถามฝั่ง backend — ถ้ายังไม่เกิน quota ผ่านต่อ

  3. ModSecurity phase 1-2

    payload ตรง signature SQLi classic (rule กลุ่ม 942xxx) ได้ anomaly score สูงเกิน threshold (5 ที่ Edge / 10 ที่ Main)

  4. Custom rule ไม่ match

    เพราะ payload ไม่มี keyword testattack/pwd01/admin1/seminar

  5. Deny

    ModSecurity ตัดสินใจ deny ส่ง HTTP 403 (custom page 403.html) เขียน log เต็ม (headers, body, matched rule id, anomaly score)

  6. ปรากฏใน Dashboard ทันที

    log forwarder ส่งเข้า ClickHouse → admin เห็นทันที พร้อมกดปุ่ม "Generate mitigation candidate" เพื่อ auto-suggest custom rule เพิ่ม

§6 แนวทางพัฒนาต่อ

  • แก้ healthcheck — override ให้ยิงไปที่ http://127.0.0.1:8080/healthz (endpoint มีอยู่แล้ว) แทนการพึ่ง default ของ base image — แก้ได้ทันทีไม่กระทบ logic อื่น
  • เพิ่ม custom rule ที่มีความหมายจริง — ใช้ blast-radius simulator ที่มีอยู่แล้วช่วยทดสอบ rule ใหม่ก่อน deploy
  • เชื่อม mitigation-candidate เข้ากับ alert pipeline — ต่อกับ telegram_listener ให้ auto-suggest rule ทันทีที่เจอ anomaly ใหม่
  • ทดสอบ payload_normalizer กับ WAF bypass technique จริง — payload-padding evasion และเทคนิค bypass ยุค 2026
