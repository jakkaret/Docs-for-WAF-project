14 ฟังก์ชันสำคัญ — ไล่ทีละบรรทัดจาก source code จริง

รูปแบบเดียวกันทุกฟังก์ชัน: caller → function → internal calls → external calls → DB/cache/queue → return พร้อมจุดตรวจความปลอดภัยและว่า sync หรือ async

ฟังก์ชันที่ทำให้ทั้งเครื่องค้าง

save_hybrid_log() เรียก boto3 put_item แบบ synchronous ไป DynamoDB ข้ามภูมิภาคตรงๆ ใน async event loop โดยไม่ผ่าน executor — ทุกครั้งที่บันทึก log 1 บรรทัด event loop จะหยุดรอทั้งก้อน รวมถึง accept() connection ใหม่ด้วย ดูข้อ 3 ด้านล่าง

§1 get_current_user() — จุดสถาปนา authentication เพียงจุดเดียว

dashboard/backend/services/rbac.py:18 · caller: ทุก endpoint ที่ต้อง login

FastAPI Depends → get_current_user(request, credentials) → _extract_token(): Authorization: Bearer <token> → หรือ cookie "access_token" ไม่มีทั้งคู่ → 401 Not authenticated → AuthService.decode_token() → jose.jwt.decode(HS256) JWTError → 401 Invalid or expired token → AuthService.get_user_by_id(user_id) → DynamoDB waf_users.get_item() [ข้ามเครื่อง, sync, ทุกครั้ง — ไม่มี cache] ไม่พบ → 401 User not found → return user (dict เต็ม: user_id, email, username, role, ...)

role อ่านจาก DynamoDB สด ไม่ใช่จาก JWT claim — เพิกถอนสิทธิ์มีผลทันที แลกกับ latency DynamoDB ทุก request

§2 require_admin() / require_viewer_or_above() / verify_origin_ownership()

services/rbac.py:61,70,79

require_admin(user) → role != "admin" → 403 require_viewer_or_above(user) → role ∉ {viewer, admin} → 403 verify_origin_ownership(origin_id, user) → DynamoDBService().get_origin_by_id(origin_id) → ไม่พบ / status=="deleted" → 404 Origin not found → origin["admin_user_id"] != user["user_id"] → 403 You do not own this origin → return origin

มีแค่ 2 role ในระบบ: admin, viewer — ตาราง waf_user_roles ที่ออกแบบไว้สำหรับ role ต่อ origin มี 0 รายการ ยังไม่ถูกใช้ · verify_origin_ownership ตอบ 404 ต่างจาก 403 ทำให้ยืนยันได้ว่า origin id นั้นมีตัวตนอยู่จริง (information disclosure ระดับเบา)

§4 frp_webhook_gatekeeper() vs verify_agent() — สองด่านตรวจ tunnel

frp_webhook_gatekeeper() — api/tunnels.py:212

Login: ตรวจ privilege_key ผ่านได้ทั้ง legacy token (ฝังในซอร์ส) และ JWT · NewProxy: _extract_raw_token() ไม่ได้รับ identity เลย → reject เสมอ · CloseProxy: allow · op อื่น: reject (fail-closed โดยเจตนา)

จุดเสี่ยง: legacy static token ฝังในซอร์ส ผ่านได้ทุก domain ที่ไม่ reserved

verify_agent() — api/tunnel.py:105

แยก token cwt_<origin_id>_<secret> → เทียบ digest ด้วย hmac.compare_digest → ตรวจ domain อยู่ใน tunnel_domains

ออกแบบดีกว่า: เก็บเฉพาะ digest, credential ผูก origin เดียว, ทุก error คืน 401 เดียวกัน, fail-closed เมื่อ verifier ต่อไม่ได้

§5 handle_vhost() — ส่ง request ที่ผ่าน WAF แล้วลง tunnel

/opt/cloudwaf-tunnel/server.py:350 · caller: waf-nginx

handle_vhost(reader, writer) → _read_head() อ่านจนเจอ \r\n\r\n (สูงสุด 32 KB) → _extract_host() ไม่มี Host → 400 → registry.lookup(host) ไม่พบ agent → 502 "No tunnel agent is connected for <host>" → agent.send(MSG_CONNECT) → รอ ≤10 วิ timeout → 504 · ok=False → 502 → agent.send(MSG_DATA, head) → loop: reader.read(4096) → ส่งต่อ finally: ลบ conn, ส่ง MSG_CLOSE, ปิด writer

Agent.send() ใช้ asyncio.Lock ครอบ writer เดียวที่ทุก connection ใช้ร่วมกัน — ถ้าไม่ล็อก frame จะสลับกันจนสตรีมพัง (ทำถูก)

§7 check_rate_limit() — auth_request ที่อยู่บนเส้นทางวิกฤต

§10 RuleManager, dispatch_telegram_alert, threshold proposal, escape_like_value

RuleManager — เขียน SecRule แล้ว reload nginx

escape_secrule_string() escape backslash ก่อน quote → เขียนไฟล์ → _run_docker_exec() จำกัด allowlist {("nginx","-t"),("nginx","-s","reload")} ไม่ใช้ shell=True — ป้องกัน command injection ได้จริง

dispatch_telegram_alert() — fire-and-forget

trigger เมื่อ status∈{403,429} หรือ severity สูง — ไม่มี deduplication/throttle สอดคล้องกับที่ waf_alerts มีถึง 73,927 แถว

generate_threshold_proposal() — self-tuning ที่ต้องมีคนอนุมัติ

มี guard ครบ: MIN_SAMPLES=200, MIN_ORIGINS=2, MAX_STEP=2 — แต่ waf_threshold_proposals มี 0 รายการ ยังไม่เคยถูกใช้จริง

escape_like_value() — ClickHouse

.replace("\\","\\\\").replace("'","\\'") — escape backslash ก่อน quote (เหตุผลมีคอมเมนต์ในโค้ด) ยังเป็นการต่อสตริงเข้า SQL ไม่ใช่ parameterized query แต่ปลอดภัยเท่าที่ escape ถูกต้อง
