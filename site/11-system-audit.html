§4 ช่องโหว่ความปลอดภัยระดับวิกฤต — รายละเอียดเต็ม

สถานะตอนตรวจ (29 ส.ค.) — ทุกรายการ live บนระบบ production ในวันนั้น ระบุตำแหน่งไฟล์/บรรทัด/endpoint ครบ ส่วนค่า secret/token จริงไม่แสดงตรงนี้เพื่อไม่เพิ่มช่องทางใหม่ อัปเดต 30 ส.ค.: ทั้ง 6 ข้อถูกแก้และทดสอบซ้ำแล้ว — ดูหลักฐานการแก้ที่ หน้า 13

C1 · FRP tunnel token รั่วสู่สาธารณะ + port เปิดอินเทอร์เน็ตCRITICAL ✅ FIXED 30 ส.ค.

/etc/frp/frps.toml บน Main ตั้ง auth.method = "token" เป็น auth เดียวที่มี — token เดียวกันนี้ hardcode ใน Tunnels.tsx (บรรทัด 62, 72) จึงถูก compile เข้า JavaScript bundle

GET http://178.104.53.123:8000/assets/index-CC3Wg3XF.js → 200, 1,026,021 bytes — ดาวน์โหลดได้โดยไม่ต้อง login พบ token คงที่ปรากฏอยู่ในไฟล์ 2 ครั้ง (ค่าจริงดูได้จาก source ตรง Tunnels.tsx:62,72) Port 7000 (frps bindPort) เปิดสู่อินเทอร์เน็ตยืนยันด้วยการสแกนจริง

ผลกระทบ: ใครก็ตามที่เปิดหน้า dashboard (หรือ curl ไฟล์ JS ตรงๆ) จะได้ tunnel token ไป และเชื่อมต่อ FRP client เข้าระบบได้ — ต้อง rotate token + ย้าย token ออกจาก frontend bundle เป็นอันดับแรก

C2 · Control API เปิดสู่อินเทอร์เน็ตโดยไม่ได้ตั้งใจCRITICAL ✅ FIXED 30 ส.ค.

ufw บน Main ตั้ง 8070 ALLOW IN 45.154.26.91 เท่านั้น แต่ docker-proxy publish port ผ่าน chain ที่ ufw ไม่ควบคุม — ทั้งอินเทอร์เน็ตเข้าถึงได้ ทดสอบจากภายนอกโดยไม่ใส่ token: GET /docs → 200 (Swagger เปิดสาธารณะ), GET /api/sync/bundle → 200 (ruleset WAF ทั้งชุด)

ทำให้แย่ลงอีก: CONTROL_TOKEN hardcode ใน docker-compose.yml ที่ track อยู่ใน git — ใครเห็น repo ก็เขียน blocklist ได้

C3 · Caddy บน Main รัน config ที่หายไปจากดิสก์แล้วCRITICAL ✅ FIXED 30 ส.ค.

ไฟล์บน host (inode 157112, 428 bytes, block เดียว) ≠ ไฟล์ที่ container ใช้จริง (inode 138459, 1,467 bytes, 3 blocks รวม protected sites) — host ถูกแก้หลัง container start ด้วยวิธีที่สร้าง inode ใหม่ ทำให้ bind mount ยังชี้ inode เก่าที่ค้างในหน่วยความจำ

ระเบิดเวลา: ถ้า caddy-ssl-termination restart หรือเครื่อง reboot จะโหลดไฟล์ 428 bytes แทน → subdomain ที่ถูกป้องกันทั้งหมดหยุดทำงาน + TLS พัง (mount เป็น read-write จึงแก้จาก container ได้ด้วย)

C4 · SQL Injection ใน AI Summary endpointCRITICAL ✅ FIXED 30 ส.ค.

dashboard/backend/api/ai_summary.py:65,76,86,96 — นำ start_time/end_time จาก request body ต่อ string เข้า SQL โดยตรง ไม่มีการ escape เข้าถึงได้โดย user ที่ login แล้วทุกคน และการสมัครสมาชิกเปิดสาธารณะ — ใครก็สมัครแล้วยิงได้

ค่าเหล่านี้ยังอาจมาจาก output ของ Gemini โดยตรง — LLM output ไหลเข้า SQL โดยไม่ผ่านการตรวจสอบ จุดอื่นที่ escape แค่ backslash (ไม่พอสำหรับ ClickHouse): analytics.py, clickhouse_service.py, logs.py, cdn.py

C5 · Tunnel ตายสนิท — เว็บที่ควรถูกป้องกันเข้าไม่ได้เลยCRITICAL ✅ FIXED 30 ส.ค.

frps clientCounts: 0 — ทุก path ของเว็บทดสอบทั้ง 4 ตัวได้ 404 ระบบไม่ได้ป้องกันอะไรอยู่จริงตอนนี้ เพราะไม่มี traffic ไหลผ่าน WAF ไปถึงปลายทางเลย

C6 · Rule drift — custom-123.confCRITICAL ✅ FIXED 30 ส.ค.

ใน git: @rx test — deploy จริงบน Edge: @rx testpj ยืนยัน: /latest → 404, /contest → 404 (ถ้าเป็นเวอร์ชัน git จะได้ 403 เพราะมี substring "test")

ความเสี่ยง: ถ้าใครรัน sync จาก repo ปัจจุบัน rule เวอร์ชัน @rx test จะ deploy ทับ — ทุก URL ที่มีคำว่า "test" จะถูกบล็อกทันที (/latest, /testimonials, /contest, /greatest)

§5 สถานะรายชั้นระบบ (สรุปย่อ)

Backend — 84 endpoints / 18 routers

ทำงานถูกต้อง: Auth (Argon2id + JWT, role อ่านจาก DB ทุกครั้ง), Telegram login (HMAC ถูกต้อง), RBAC, Rules CRUD + nginx reload, safe_regex.py (ป้องกัน ReDoS), payload_normalizer.py

พัง: Domain/SSL ทั้งหมด 404 (router ไม่ถูก mount), BOLA Guard ไม่บันทึก policy (ลืม import time), Blast Radius คำนวณจาก synthetic data 100%, /api/logs/explain คืน stub ทุกครั้ง

Frontend — React 18 + Vite + TS

หน้า Tunnels แสดง "🟢 ONLINE" hardcode ทั้งที่ tunnel ตายสนิท — backend ส่งสถานะจริงมาแล้วแต่ frontend ไม่อ่าน หน้า Traffic Logs ว่างถาวรสำหรับ non-admin หน้า ML Rules มีจุด crash ทั้งแอปถ้าเจอ row ที่ไม่มี field ที่คาด

พบตัวเลข/สถานะ hardcode 25+ จุด รวมถึงเวอร์ชัน CRS ที่ขัดกันเอง 3 แบบในหน้าต่างๆ (3.3.5 / 4.0 / 3.3)

ML — วัดจริงจาก eval_results.json

Accuracy 80.47% (ไม่ใช่ 93.40% ที่ README อ้าง), Attack recall 62.26% (พลาดโจมตี 37.7%), Attack precision 98.39% accuracy_target_passed: true เป็นค่า hardcode ตายตัว — ไม่เคยคำนวณจริง

ML ไม่มี nginx config ใดอ้างถึงเลย — อ่าน log ย้อนหลังเท่านั้น ไม่เคยบล็อก entropy feature คำนวณแล้วทิ้ง (dead code)

CDN — 2/4 องค์ประกอบผ่าน (ไม่เปลี่ยนจากที่เคยประเมิน)

GeoDNS แมป region ด้วย CIDR hardcode (subnet จำลองสำหรับ test script) ไม่ใช่ GeoIP database จริง — ต่อให้ deploy ก็ยังไม่ทำ geo-routing จริง

Cache key ไม่รวม $args → cache ตายสำหรับทุก request ที่มี query string TLS private key ของ edge commit อยู่ใน repo

§8 สิ่งที่ตรวจไม่ได้ในรอบนี้

  • Lab node ภายในเครื่อง — SSH auth ไม่ผ่านทุก user ที่ลอง ต้องได้ key ก่อน
  • สถานะ Cloudflare Tunnel บน Lab — ตรวจไม่ได้เพราะเข้า Lab ไม่ได้ (เอกสารเก่าระบุว่ามี service เปิดพอร์ต 80 ตรงสู่อินเทอร์เน็ตข้าม WAF — ยังไม่ยืนยันจริงหรือไม่ในตอนนี้)
  • การทดสอบ write ของ Control API — ระบบบล็อก write โดยไม่มี token ยืนยันจาก source code แทน
  • Rate limiting และ Cache HIT ว่าทำงานถูกต้องหรือไม่ — ต้องรอ tunnel กลับมาก่อนทดสอบซ้ำได้
  • Dashboard functional test (login, สร้าง origin, ดู log) — ไม่ได้ทดสอบเพราะจะสร้าง state ใหม่ในระบบ production
