03 · DASHBOARD BACKEND + API

Backend เดียวเสิร์ฟทั้ง REST API และ React SPA

ระบบจัดการ WAF/CDN แบบ multi-tenant — ผู้ใช้แต่ละคนเพิ่ม "origin" ของตัวเองให้ WAF คุ้มครอง โดยข้อมูลแยกด้วย admin_user_id ที่ผูกกับทุก origin/domain

ทำงานที่: Main Node — uvicorn main:app :8000โค้ด: /root/waf_project/dashboard/

§1 เทคโนโลยีที่ใช้

Frontend

§2 ความสามารถ (ยืนยันจาก endpoint จริงใน openapi.json)

Authentication 3 ช่องทางทำงานจริง

Local (argon2), Google OAuth 2.0, Telegram Login Widget — JWT เก็บใน HttpOnly cookie (มีคอมเมนต์ในโค้ดว่านี่คือ security fix ที่แก้แล้ว เพราะ token ใน URL หลุดไปอยู่ history/log ได้)

Origins & Domains CRUDทำงานจริง

quota 5 origin active/บัญชี (ค่า default), soft-delete + restore, verify DNS ด้วย CNAME หรือ TXT record 2 วิธี

Ownership isolation ทุก endpointทำงานจริง

verify_origin_ownership บังคับเช็ค admin_user_id ก่อนเสมอ ป้องกัน BOLA/IDOR ข้าม tenant

Rate Limiting (sliding-window)ทำงานจริง

Redis + Lua script (atomic) — fail-open by design: Redis ล่ม → ปล่อยผ่านทุก request แทนบล็อกทั้งหมด

PII Masking Engineทำงานจริง

เช็คบัตรประชาชนไทยด้วย checksum จริง, บัตรเครดิตด้วย Luhn algorithm, zero-knowledge hash สำหรับค้นหาโดยไม่เก็บค่าจริง — ออกแบบรองรับ PDPA/GDPR

Telegram Alertsทำงานจริง

ผูกบัญชีด้วย one-time code 6 หลัก (หมดอายุ 5 นาที) frontend poll ทุก 3 วิ

DNS auto-verification workerไม่ต่อสาย

dns_verification_worker.py เขียน loop สมบูรณ์ (scan ทุก 10 วิ) แต่ main.py startup ไม่เคยเรียก asyncio.create_task() ให้มัน — verify เกิดเฉพาะตอนกดปุ่มเอง

Admin approval flowไม่ครบตามคอมเมนต์

คอมเมนต์บอกว่าต้องมี approval แต่โค้ดจริงแค่ downgrade role เป็น viewer เงียบ ๆ ไม่มี flow อนุมัติจริง

Reload mode เปิดใน productionหนี้เทคนิค

uvicorn.run(..., reload=True) เหมาะกับ dev มากกว่า — กิน CPU เพิ่มและอาจ restart โดยไม่ตั้งใจ

Settings เก็บเป็นไฟล์ JSONหนี้เทคนิค

data/system_settings.json ไม่ใช่ DynamoDB — scale หลาย instance แล้วค่าจะไม่ sync กัน

§3 หลักการทำงาน

3.1 Auth flow (local login)

  1. Client ส่ง email/password

    POST /api/auth/login

  2. ดึง user จาก DynamoDB

    waf_users table ผ่าน GSI EmailIndex ก่อน ถ้าไม่มี fallback ไป scan

  3. ตรวจรหัสผ่านด้วย argon2

    verify()

  4. สร้าง JWT

    หมดอายุตาม JWT_EXPIRE_MINUTES (default 60 นาที) เซ็นด้วย HS256

  5. ส่งกลับ

    ทั้งใน response body และ HttpOnly cookie (samesite=lax, secure เมื่อ FORCE_HTTPS=true)

ชั้น RBAC checkรายละเอียด
1. อ่าน tokenAuthorization: Bearer header ก่อน ถ้าไม่มี fallback ไปอ่าน cookie
2. Decode JWTinvalid/expired → 401
3. ดึง user เต็มจาก DynamoDBยืนยันว่า user ยังมีอยู่จริง ไม่ใช่เชื่อ payload ใน token เฉย ๆ
4. require_admin / require_viewer_or_aboveเช็ค field role อีกชั้น
5. verify_origin_ownershipเฉพาะ endpoint ที่แตะ origin/domain เจาะจง กันข้าม tenant
 
Browser (React SPA)
   │  axios + JWT cookie
   ▼
FastAPI (:8000) ── CORS allow เฉพาะ origin ใน ALLOWED_ORIGINS
   │
   ├─ get_current_user / require_admin ──> decode JWT ──> DynamoDB.waf_users
   ├─ Origins/Domains API ──> verify_origin_ownership ──> DynamoDB.waf_origins / waf_domains
   │                                          └─ dns_service.py ──> DNS resolver จริง
   ├─ Rate-limit enforcement ──> Redis (Lua sliding-window script)
   ├─ Logs/Analytics API ──> clickhouse_service.py ──> ClickHouse
   │        ก่อนแสดงผล log ที่มี PII ──> pii_masker.py mask ก่อนเสมอ
   ├─ Alerts API ──> Telegram Bot API (httpx async)
   └─ Background workers (asyncio.create_task ตอน startup):
        - alert_worker() · log_forward_worker() · _cleanup_expired_codes()

§4 Scenario: ผู้ใช้ใหม่เพิ่มเว็บไซต์เข้าระบบ

  1. สมัครสมาชิก

    คนแรกในระบบ → role admin อัตโนมัติ, คนถัดไป → viewer เสมอแม้ขอ role admin

  2. ล็อกอิน

    ได้ JWT cookie

  3. เพิ่ม Origin

    กรอก label + IP + port → เช็ค quota (ไม่เกิน 5 active) → สร้างเป็น status: pending

  4. เพิ่มโดเมน

    ระบบสร้าง verification_token คืน dns_instructions (CNAME → cdn.local, TXT ที่ _waf-challenge.example.com)

  5. ตั้งค่า DNS จริงแล้วกด Verify

    backend resolve CNAME/TXT จริงผ่านอินเทอร์เน็ต

  6. ตรง → dns_verified=True

    Caddy เรียก check-ssl-allowed แล้วออก TLS cert อัตโนมัติ

  7. Traffic เริ่มถูกป้องกัน

    route ผ่าน edge WAF ไปยัง origin — ทุก request โดน ModSecurity CRS ตรวจก่อนเสมอ
