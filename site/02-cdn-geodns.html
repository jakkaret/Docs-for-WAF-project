02 · CDN + GEODNS

Multi-region CDN: เขียนเสร็จ ผ่านทุก test — แต่ยังไม่เคย deploy จริง

ส่วนต่อขยายของแพลตฟอร์มให้ client แต่ละภูมิภาค (SG/JP/TH) ถูก route ไปยัง edge ที่ใกล้ที่สุดผ่าน GeoDNS โดยแต่ละ edge ทำหน้าที่ทั้ง cache และ WAF ในตัว

โค้ดอยู่ที่: /root/waf_project/cdn/ (Main Node)เอกสารต้นทาง: CDN_BUILD_SHEET.md, NEXT_STEPS.md

สำคัญ — ต้องแยกสองสถานะ

โค้ดของฟีเจอร์นี้ "เขียนเสร็จและผ่านการทดสอบแล้ว" แต่ "ไม่ได้รันอยู่จริงบน production" — สองอย่างนี้คนละสถานะกันโดยสิ้นเชิง

§1 เทคโนโลยีที่ใช้

ส่วนประกอบเทคโนโลยี
Edge reverse proxy + WAFowasp/modsecurity-crs:nginx × 3 instance (SG/JP/TH)
GeoDNS resolverPython dnslib — custom DNS server ตอบ A record ตาม client IP
Control APIFastAPI + SQLite (control.db)
Purge APIFastAPI — ลบ cache file ตาม MD5 ของ cache key
Stats collectorPython — tail access log ต่อ region, expose /metrics
Cache storeNginx proxy_cache แยก volume ต่อ region
NetworkDocker bridge cdn-net (172.28.0.0/16) เชื่อม waf-net

§2 สถานะ — เขียนเสร็จ vs รันอยู่จริง

Health check ทั้ง 3 edge + purge-apiผ่าน test

ตอบ ok ครบทุกตัวบนเครื่อง dev

Cache MISS → HITผ่าน test

request แรก MISS, request ที่สอง HIT ทำงานถูกต้อง

Purge cache ข้าม 3 regionผ่าน test

total_removed=3 พร้อมกันทุกภูมิภาค

Bypass policyผ่าน test

query string, Cache-Control: no-cache, session cookie, Authorization header → บังคับ BYPASS ถูกต้อง

WAF ทำงานหลัง cache layerผ่าน test

ทดสอบ /testattack ได้ 403 แม้อยู่หลัง cache

GeoDNS auto-select regionผ่าน test

probe IP วง 172.28.11/22/33.x ตอบ region SG/JP/TH ถูกต้องตามลำดับ

คำสั่งทดสอบใน build sheet ระบุ path /Users/boss/project/waf_project/cdn — เครื่อง dev บน local Mac ไม่ใช่ production จริง

ยืนยันแล้วว่า "ไม่ได้รันอยู่" บน production

Main Node (178.104.53.123)

docker ps -a --filter name=cdn- ไม่มี container cdn-* เลยแม้แต่ตัวเดียว

Edge Node (45.154.26.91)

มี container ขึ้นต้น cdn- จริง แต่เป็นคนละชุดจาก /root/edge_node/ — edge เดี่ยวธรรมดา ไม่ใช่ ส่วนหนึ่งของ multi-region stack

Dashboard ผูกกับโมเดล 2-node ไม่ใช่ SG/JP/TH

อ่าน dashboard/backend/api/cdn.py ที่รันจริง — REGIONS_META มีแค่ TH (Edge Node จริง) กับ MAIN (Main Node จริง) เท่านั้น ไม่ตรงกับที่ build sheet บันทึกว่าแก้เป็น SG/JP/TH แล้ว — นอกจากนี้ GET /api/cdn/latency ส่งค่า hardcode ทั้งหมด (Bangkok 14ms, Singapore 35ms, Tokyo 68ms ฯลฯ) ไม่ได้วัดจาก edge จริง เป็น mock data สำหรับ demo UI

§3 หลักการทำงาน

3.1 GeoDNS routing (geodns/server.py)

  1. DNS server ฟัง UDP/TCP 53

    ใช้ library dnslib ภายใน container

  2. อ่าน client_ip

    เมื่อได้รับ query สำหรับ cdn.local

  3. เทียบ REGION_CIDRS

    SG=172.28.11.0/24, JP=172.28.22.0/24, TH=172.28.33.0/24 — ไม่ตรงเงื่อนไขไหน fallback เป็น TH

  4. health_check_loop() ทุก 10 วิ

    เก็บสถานะใน NODE_STATUS

  5. Failover ตาม priority

    SG/JP → TH, TH → SG ถ้า region ที่เลือก DOWN

  6. ตอบ A record + TTL 20s

    ให้ client re-resolve บ่อยพอรับ failover ได้เร็ว

[Client] --DNS query cdn.local--> [GeoDNS :5533]
                                       |  (เลือก region ตาม client IP + health status)
                                       v
                              A record ชี้ไป [Edge ตาม region: SG:8081 / JP:8082 / TH:8086]

[Client] --HTTP request--> [Edge Nginx + ModSecurity]
                                |
                          (เช็ค cache ก่อน)
                          MISS --> proxy ไปยัง [Origin: waf-nginx:8080 (DVWA หลัง WAF หลัก)]
                                       |
                                  ตอบกลับ + เก็บลง cache
                          HIT  --> ตอบจาก cache ทันที ไม่แตะ origin

[Dashboard] --POST /purge--> [purge-api :8090] --ลบ cache file--> [ทุก region ที่ระบุ]

§4 แนวทางพัฒนาต่อ

  1. Deploy ของจริง

    docker compose -f docker-compose-cdn.yml up -d --build บน production แล้วรัน test suite ซ้ำ

  2. เชื่อม dashboard เข้ากับ SG/JP/TH จริง

    แก้ REGIONS_META, ลบ hardcoded latency แทนด้วยการวัดจริง (มี pattern ให้ใช้แล้วสำหรับ TH/MAIN)

  3. แทนที่ CIDR จำลองด้วย GeoIP จริง

    ผูก choose_region_for_ip() เข้ากับ MaxMind GeoLite2

  4. Distributed rate limiting

    Redis+Lua (มี waf-redis รันอยู่แล้วบน Main Node พร้อมใช้งาน) — ตาม NEXT_STEPS.md Phase 4
