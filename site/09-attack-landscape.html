09 · ภูมิทัศน์การโจมตี 2025–2026

ทำไมต้องมี WAF: สาเหตุ วิวัฒนาการ และข้อจำกัดของการป้องกันในยุค AI

รวบรวมและตรวจสอบจาก 120+ แหล่งอ้างอิงผ่าน Exa Research (2 subagent เฉพาะทาง) ประกอบกับความรู้พื้นฐานด้านความปลอดภัยเว็บแอปพลิเคชัน

§1 สาเหตุพื้นฐานที่ทำให้เกิดการโจมตี

  • Trust boundary ที่พัง — server เชื่อข้อมูลจากฝั่ง client โดยไม่ตรวจสอบเพียงพอ รากของ SQLi และ XSS
  • Human error — misconfiguration, รหัสผ่านอ่อนแอ, ไม่อัปเดตแพตช์ทันเวลา
  • แรงจูงใจทางเศรษฐกิจ — ข้อมูลมีมูลค่าสูงในตลาดมืด, botnet เช่าใช้ได้ราคาถูก (Attack-as-a-Service)
  • ความซับซ้อนของระบบ — microservices, third-party library จำนวนมาก ขยาย attack surface
  • Legacy code — เขียนก่อน threat model ปัจจุบันจะเป็นที่รู้จัก

§2 วิวัฒนาการการป้องกันตามยุค — ต่อประเภทการโจมตี

ประเภทสาเหตุวิวัฒนาการการป้องกันผลลัพธ์
SQL Injectionต่อ input เข้า SQL command ตรง ๆPrepared Statements → WAF signature filteringลดมากในระบบสมัยใหม่ ยังพบใน legacy
XSSแสดงผล input โดยไม่ escapeOutput encoding → CSP → framework auto-escape (React/Vue)ลดมากในเว็บที่ใช้ framework สมัยใหม่
CSRFcookie ส่งอัตโนมัติไม่ตรวจ originCSRF token manual → SameSite cookie (default Lax)แทบหมดไปเมื่อตั้งค่าถูกต้อง
DDoSทรัพยากรจำกัด, protocol ไม่ตรวจแหล่งที่มาRate limiting → CDN/Anycast → ML behavioral detectionขนาดโจมตีใหญ่ขึ้นเรื่อย ๆ (Mirai) แต่ CDN ดูดซับได้ดีขึ้น
Credential Stuffingใช้รหัสผ่านซ้ำข้ามเว็บRate limiting → CAPTCHA → MFA → Passkey/WebAuthnMFA เริ่มถูก AiTM phishing บายพาสได้
Supply ChainDependency tree ใหญ่เกินตรวจสอบSBOM, Dependency scanning, Package signingเพิ่งเริ่ม mainstream ยังเป็นจุดอ่อนสำคัญ
Zero-day / RCEMemory safety / logic flaw ที่ยังไม่รู้จักPatch management, virtual patching, sandboxingไม่มีป้องกันสมบูรณ์ 100% ลดผลกระทบด้วย defense-in-depth

แนวโน้มรวม: ก่อนปี 2010 เน้น perimeter defense (firewall ชั้นเดียว) — หลังปี 2010 เปลี่ยนไปใช้ defense-in-depth + zero trust + shift-left security

§3 การโจมตียุคใหม่ (2025–2026)

3.1 การโจมตีที่ขับเคลื่อนด้วย AI

AI-generated phishing

click-through 54% เทียบ 12% ของฟิชชิงมนุษย์เขียน — โจมตีสถาบันการเงินเพิ่มขึ้น 1,265% ตั้งแต่ปี 2022

Prompt Injection

อันดับ 1 OWASP Top 10 for LLM 2025 · สำเร็จ 50–84% · แอปผสาน LLM 86% มีช่องโหว่ (จาก 36 แอปที่ตรวจ)

AI-assisted vuln discovery

DARPA AI Cyber Challenge: พบช่องโหว่ 54 รายการใน 54 ล้านบรรทัดภายใน 4 ชม. · Mean Time To Exploit ติดลบ 7 วัน

3.2 Autonomous AI Attack Agent

กรณี GTG-1002 (พ.ย. 2025)

กลุ่มที่ได้รับการสนับสนุนจากรัฐจีนใช้ Claude เป็นตัวขับเคลื่อนหลักโจมตีองค์กรทั่วโลก ~30 แห่งแบบอัตโนมัติ 80–90% ด้วยความเร็วหลายพัน request/วินาที — กรณีแรกที่เปิดเผยต่อสาธารณะว่า LLM เป็นศูนย์กลางควบคุมปฏิบัติการโจมตีจริง

ระยะเวลาจาก initial access ถึง exploitation ลดลงจาก 8+ ชั่วโมง (2022) เหลือ 22 วินาที (2025) — CrowdStrike รายงานการโจมตีที่ใช้ AI เพิ่มขึ้น 89% ปีต่อปี

3.3 API Security Threats

0ช่องโหว่ API ทั้งหมดเป็น BOLA
0bot ขั้นสูงมุ่งเป้าที่ API
0การโจมตีเว็บเกี่ยวข้องกับ API
0USD/ปี สูญเสียจาก API fraud (การเงิน)

BOLA ติดอันดับ 1 ใน OWASP API Security Top 10 — เหตุการณ์จริง: ธนาคารกลางรัสเซียสูญเสีย 2 พันล้านดอลลาร์จากการ exploit BOLA (2016)

3.4 Deepfake-Enabled Social Engineering

กรณี Arup: สูญ 25.6 ล้านดอลลาร์ จากวิดีโอคอลเสียงโคลนจากคลิปต้นฉบับเพียง 3 วินาที · Q1 2025 deepfake vishing เพิ่มขึ้น 1,633%

§4 ข้อจำกัดของกลไกป้องกันปัจจุบัน

กลไกป้องกันอะไรวิธีบายพาส / ข้อจำกัดจริง
WAFกรอง payload อันตรายEncoding/obfuscation, protocol manipulation, payload fragmentation/padding
MFA แบบดั้งเดิมcredential รั่วไหลอย่างเดียวAiTM phishing (Evilginx, EvilProxy) ขโมย session token หลังผ่าน MFA — เพิ่มขึ้น 146%/ปี, ~40,000 ครั้ง/วัน
Session token/cookieหลักฐานยืนยันตัวตนInfostealer (LummaC2, RedLine) ขโมยคุกกี้ 94 พันล้านตัวในปี 2025
Rate limitingbrute force, DDoSDistributed traffic กระจายหลาย PoP, burst attack สั้นกว่า static threshold
CAPTCHAแยกมนุษย์กับ botLLM multimodal แก้ได้เองอัตโนมัติ สำเร็จสูงถึง 99%
ประเด็นสำคัญที่สุด

จุดศูนย์กลางภัยคุกคามย้ายไปที่ "post-authentication token theft" — MFA ป้องกันได้แค่ช่วงเวลายืนยันตัวตนเท่านั้น เมื่อ session token ถูกขโมยไปหลังจากนั้น MFA จะไม่มีผลใด ๆ อีก · 88% ของการรั่วไหลข้อมูลเว็บแอปปี 2025 เกี่ยวข้องกับ credential/session token ที่ถูกขโมย

§5 บทสรุปและแนวโน้ม

  1. การโจมตีคลาสสิกลดลงชัดเจน

    SQLi/XSS/CSRF ในระบบที่ใช้ framework สมัยใหม่ แต่ยังเป็นปัญหาในระบบ legacy

  2. ศูนย์กลางภัยคุกคามย้ายไปที่ post-authentication token theft

    แทนการขโมย credential แบบเดิม ทำให้ MFA ดั้งเดิมหมดประสิทธิภาพ

  3. AI เป็นทั้งเครื่องมือโจมตีและป้องกัน

    ฝั่งโจมตีปรับตัวเร็วกว่าฝั่งป้องกันในปัจจุบัน

  4. API คือพื้นที่การโจมตีหลักใหม่

    BOLA ยังเป็นจุดอ่อนที่พบบ่อยที่สุด — ตรงกับเหตุผลที่ระบบนี้มี vAmPI + bola_guard.py

  5. คำแนะนำเชิงปฏิบัติ

    เปลี่ยนจาก OTP/Push ไปใช้ phishing-resistant MFA (FIDO2/Passkey) ร่วมกับตรวจ device compliance และ behavioral detection แบบ real-time
