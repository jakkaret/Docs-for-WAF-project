§3 Critical ที่เจอระหว่างทาง — แก้ก่อน deploy

Critical 1 · คำอธิบายทำให้การตรวจจับล่มFIXED

fallback ของ explain_attribution เรียก item.get() โดยไม่เช็คว่าเป็น dict ก่อน — entry ที่ไม่ใช่ dict ทำให้ raise หลุดออกไปจนถึง 500 ทั้ง request ขัดกฎที่ตั้งไว้ว่า "การตรวจจับต้องอยู่เหนือคำอธิบายเสมอ"

น่าสังเกต: รอบก่อนหน้า implementer รายงานเองว่า "ขยาย try ครอบทั้งเมธอดแล้ว" แต่โค้ดจริงไม่ใช่ — ถ้าเชื่อรายงานอย่างเดียวก็จะปล่อยผ่าน

แก้แบบ defense-in-depth 3 ชั้น (fallback ทน non-mapping / final return อยู่ในเขตป้องกัน / call site guard) แล้วยิงทดสอบเอง 9 รูปแบบ ไม่มีอันไหน raise

Critical 2 · Cross-tenant SQL Injection ผ่าน domain registrationMITIGATED — ไม่ใช่ปิดสนิท

endpoint เก่า POST /api/domains ไม่มี validation เลยแม้แต่ .strip() เขียนเข้า table เดียวกับ endpoint ใหม่ที่ไหลต่อไป ClickHouse ที่ escape ด้วย replace("'", "\\'") เท่านั้น — พิสูจน์ exploit ได้จริง: ส่ง x\' OR 1=1 -- แล้ว backslash ของผู้โจมตี "กินตัว escaper เอง" ทำให้ quote ปิด string จริง ข้าม tenant filter ได้ (registration เปิดสาธารณะ)

นี่เป็นช่องโหว่ที่อยู่บน production มาก่อนรอบนี้แล้ว ไม่ได้เกิดจากงานที่เพิ่งทำ — แต่เกือบ deploy ทับโดยรู้ทั้งรู้ ถ้าไม่จับได้ตอน review

แก้ด้วย validator ตัวเดียวกันทั้ง 2 endpoint — แต่จงใจไม่แตะตัว escaping เพราะเป็น sink เดียวกับ finding H4 ในหน้า 11 ที่ควรแก้ด้วย parameterized query (คนละเรื่องกับ entry validation) sink เดิมยังเข้าถึงได้จากทางอื่น (origin.label, query param search/origin) ที่รอบนี้ยังไม่ได้แตะ

bug เล็กอื่นที่เจอและแก้ไปด้วย

rules.py delete_rule — raise HTTPException(404) อยู่ใน try แล้วโดน except Exception กลืน → ลบ rule ที่ไม่มีอยู่ได้ 500 ตลอด ไม่มีทางได้ 404 จริง (แก้แล้ว)

§5 ข้อจำกัดที่ต้องพูดตรงๆ

อย่าพูดเกินจริง — คำเตือนจากเอกสารต้นฉบับ

อย่าอธิบายว่า "ปิดช่องโหว่ SQL Injection แล้ว" — สิ่งที่ทำคือปิดเส้นทางหนึ่งด้วย entry validation ส่วนตัว sink (การต่อ string เข้า SQL แบบไม่ parameterize) ยังอ่อนอยู่และเข้าถึงได้จากทางอื่น (origin.label ไม่มี validation, query param search/origin) — พูดเกินกว่านี้จะเป็นปัญหาตอน defense ถ้าอาจารย์ไล่ดูโค้ดจริง ทางแก้ที่ถูกต้องคือ parameterized query ทั้งหมด (finding H4 ในหน้า 11) ซึ่งควรเลื่อนความสำคัญขึ้นจากสิ่งที่รอบนี้พิสูจน์แล้วว่าเข้าถึงได้จริง

Deferred เล็กๆ: CI job test-ml ยังไม่ pin เวอร์ชัน sklearn (โค้ดมี defensive normalization เพราะเรื่องนี้พอดี) · CI test-backend ยังมี LocalStack sidecar ที่ไม่ถูกใช้แล้ว

นอก scope ที่ยังคาอยู่ (ไม่เปลี่ยนจากเดิม): except Exception → 500 อีก ~30 จุด · escaping ที่อ่อนใน 3 ไฟล์ (H4) · Playwright spec selector ไม่ตรง DOM · entropy dead code · Cloudflare tunnel bypass บน Lab (ดู หน้า 14 — ยังเป็น priority สูงสุดที่ยังไม่ปิด)
