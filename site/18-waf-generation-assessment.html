18 · GENERATION ASSESSMENT — 1 ก.ย. 2026

WAF Gen ไหนกันแน่ — ประเมินตรงไปตรงมา ไม่อวย

คำถามที่ผู้ใช้ถาม: "WAF ตอนนี้มีกี่ Gen ต่างยังไงบ้าง ของผมอยู่ในระดับไหน ขอแบบไม่อวย" — เทียบกับ framework การแบ่ง generation จริงจากอุตสาหกรรม (F5, Check Point, Levo.ai) ไม่ใช่นิยามที่ตั้งเอง แล้ววางสถานะจริงของโปรเจกต์ทับทีละข้อ

ผลสรุป เอนจินที่บล็อกจริง = Gen 1 (signature-based) — ML ที่มีเป็นของจริงแต่ยังไม่ถึงเกณฑ์ Gen 3

§1 WAF แบ่งเป็นรุ่นไหนบ้าง — นิยามจากอุตสาหกรรมจริง

รุ่นหลักการตัวอย่าง
Gen 1
Signature-based		จับ pattern ที่รู้จักแล้ว (regex/rule ตายตัว) ต้องคนอัปเดต rule เอง จับ zero-day ไม่ได้ false positive สูงModSecurity+CRS แบบดั้งเดิม, WAF appliance รุ่นเก่า
Gen 2
Behavioral / Session-aware		เพิ่ม tracking session, ให้ risk score ตามพฤติกรรม (บอท, rate, pattern การเข้าใช้) ลดพึ่งพา signature อย่างเดียวระบบที่มี bot detection + session risk
Gen 3
Next-Gen WAF (ML-driven)		เทรนจาก attack data จำนวนมาก จับ pattern ใหม่ที่ไม่เคยเห็นได้ ไม่ต้องรอคนเขียน rule near-zero-configCloudflare/F5/Imperva รุ่นปัจจุบัน
Gen 4
WAAP		รวม WAF + Bot Management + API Security (schema-aware) + DDoS + client-side protection (Magecart) + edge หลายภูมิภาค + threat intel แชร์ข้าม customerCloudflare, Akamai, Imperva ตัวเต็มปี 2025–26

อ้างอิง: F5 — From rules to risk · Check Point — What Is a Next-Gen WAF? · Levo.ai — What Is WAAP?

§2 โปรเจกต์นี้อยู่ตรงไหน — ประเมินตรงๆ

เอนจินที่บล็อกจริงคือ Gen 1

ModSecurity + OWASP CRS signature-based ล้วนๆ — เทคโนโลยีเดียวกับที่ commercial product ใช้เมื่อ 10–15 ปีก่อน ไม่ต่างจาก WAF ตัวเก่าที่สุดในตลาด

ML ที่มีอยู่คือของจริง แต่ยังไม่ถึงระดับ Gen 3

เกณฑ์ Gen 3สถานะจริงของโปรเจกต์
ตัดสินใจบล็อกเองแบบ real-time❌ ไม่ auto-block เลย — เป็นแค่คำแนะนำให้คนอนุมัติ (human-in-the-loop)
ความแม่นยำเพียงพอให้เชื่อถือ❌ attack recall จริง 62.26% — ดูตัวเลขเต็มและที่มาของการแก้ไขที่ หน้า 17 §9
Closed-loop retraining (เรียนรู้จาก traffic ใหม่)❌ เทรนครั้งเดียว ไม่มี pipeline ป้อนกลับเลย (ยืนยันด้วย grep ทั้ง repo)
Feature attribution / อธิบายได้✅ มีจริง — per-request attribution ภาษาไทย ดูหน้า 16

Gen 2 features — ไม่มีเลยสักอย่าง

ไม่มี bot management, ไม่มี session-based risk scoring, ไม่มี challenge/captcha — ยังไม่ถึง Gen 2 ด้วยซ้ำในมิตินี้

Gen 4 / WAAP — ไม่ถึงแม้แต่จะเข้าใกล้

Featureสถานะ
API schema-aware protection❌ ไม่มี
Client-side / Magecart protection❌ ไม่มี
Multi-region edge จริง⚠️ CDN 3-region (SG/JP/TH) เขียนโค้ดเสร็จ ผ่าน test บน dev แล้ว แต่ไม่เคย deploy จริงข้ามภูมิภาคเลย — ปัจจุบันมี Edge node จริงแค่ 1 ตัว
RASP❌ ไม่มี
Threat intel แชร์ข้าม tenant❌ ไม่มี

§3 สรุป

คำตัดสิน

คือ Gen 1 WAF ที่มี prototype ML แปะเป็นชั้นทดลองข้างๆ ยังไม่ไว้ใจให้ตัดสินใจเอง ไม่ใช่ Next-Gen WAF ตามนิยามอุตสาหกรรม แม้โค้ด ML/AI Copilot/explainability จะดูทันสมัย

สำหรับ thesis/capstone — นี่คือ scope ที่สมเหตุสมผล จุดขายที่ตอบได้จริงในห้องสอบคือ "เข้าใจข้อจำกัดของ ML แล้วออกแบบให้ human-in-the-loop เพราะ recall ไม่พอ" ไม่ใช่ "สร้าง Next-Gen WAF"

คำเตือนสำหรับ defense

ถ้าไปเคลม Gen 3/WAAP จะโดนซักได้ง่ายมาก เพราะตัวเลขและ feature ไม่ซัพพอร์ตคำอ้างนั้นจริง — ตอบตามตารางข้างบนแทน จะดูน่าเชื่อถือกว่าและตอบคำถามลึกได้มั่นใจกว่า

§4 ถ้าจะพัฒนาต่อให้ถึง Gen 4 — ต้องทำอะไรบ้าง

4.1 Bot Management

ยังไม่มีเลย — Gen 2 ก็ยังไม่ถึง ต้องสร้าง fingerprinting (TLS/JA3, canvas/behavior), session risk scoring, challenge (CAPTCHA/JS) แทนการ block ตรงๆ — งานใหญ่ ต้องมี dataset บอทจริงมาเทรน/tune

4.2 API Security (schema-aware)

ต้อง parse OpenAPI/schema ของ origin แล้วตรวจ request ตาม schema จริง (ไม่ใช่แค่ regex บน URL) + auto-discover endpoint ที่ origin ไม่เคยประกาศไว้ (shadow API detection)

4.3 Multi-region Edge จริง

โค้ด CDN 3-region เขียนเสร็จแล้ว แต่ต้อง deploy จริง — เช่าเครื่องเพิ่มอีก 2 ภูมิภาค + GeoDNS จริง + sync rule ข้าม edge ให้ทำงานพร้อมกัน ไม่ใช่แค่โค้ด

4.4 Client-side Protection (Magecart-class)

ต้อง inject JS monitor ฝั่ง browser ตรวจ script ที่ผิดปกติ (เช่น skimmer ขโมยบัตรเครดิต) — สถาปัตยกรรมคนละชั้นกับ WAF เดิมทั้งหมด เริ่มจากศูนย์

4.5 RASP

ต้องฝัง agent เข้าไปใน runtime ของแอปเป้าหมายเอง (Java/Node/.NET) ไม่ใช่แค่ที่ perimeter — เกินขอบเขตของ "WAF ข้างหน้า origin" ที่ออกแบบไว้ตอนนี้เลย ต้องเปลี่ยนสถาปัตยกรรมพื้นฐาน

4.6 Threat Intel ข้าม tenant

ต้องมี traffic จากลูกค้าจริงจำนวนมากพอจะเห็น pattern ร่วม — ข้อนี้ทำไม่ได้เลยจนกว่าจะมีผู้ใช้จริงหลายรายในสเกลใหญ่ ไม่ใช่แค่เรื่องเทคนิค

4.7 ยกระดับ ML ให้ auto-block ได้ (เงื่อนไขของ Gen 3 ที่ยังไม่ผ่านด้วยซ้ำ)

ต้องดัน recall จาก 62% ขึ้นไปในระดับที่ไว้ใจได้ (>90%+) + closed-loop retraining + calibrate confidence — ตามที่ CLAUDE.md ระบุไว้แล้วว่าเลื่อนหลังสอบจบ

ทำไม่ทันใน 1 เดือนแน่นอน — ไม่ใช่แค่ "เยอะ" แต่บาง item เปลี่ยน scope ทั้งหมด

ข้อ 4.5 (RASP) กับข้อ 4.6 (threat intel ข้าม tenant) ไม่ใช่ปัญหาที่แก้ด้วยเวลา/แรงเพิ่ม — ข้อ 4.5 ต้องเปลี่ยนสถาปัตยกรรมจากรากฐาน ข้อ 4.6 ต้องมี user base จริงที่ยังไม่มี

คำแนะนำ: อย่าตั้งเป้า Gen 4 เป็น scope thesis เด็ดขาด — ถ้าอยากมีจุดขาย "ก้าวข้าม Gen 1" แนะนำเลือกแค่ 1 อย่างที่เข้าเงื่อนไขเวลา+โครงสร้างที่มีอยู่แล้วจริง: ข้อ 4.3 (deploy multi-region ที่เขียนเสร็จแล้ว) เพราะโค้ดพร้อม เหลือแค่ deploy — ตรงกับ priority "CDN ให้จริงครบ" ที่ CLAUDE.md วางไว้อยู่แล้ว ไม่ต้องเพิ่ม scope ใหม่
